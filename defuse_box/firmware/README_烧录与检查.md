# 拆弹箱基础检查 V1.0

2026-11-02。独立工程，目标名 **Defuse_Base**，采用 STM32F10x 标准外设库、Cortex-M3 CMSIS，主频沿用已调通的 HSI/PLL 64MHz。支持 WHO_AM_I=0x68 的 MPU6050 及 0x70 的 MPU6500 兼容身份；保留身份复读、寄存器回读和新数据检测。

这一版用于确认接线和单模块工作。三关解谜、倒计时、密码生成和自动开锁将在下一阶段实现。当前显示的是中文硬件检查页面，不会出现游戏开始按钮。

## 先烧录

1. 完整解压包，打开本目录的 `Project.uvprojx`，不要只拖出一个工程文件。选择唯一目标 **Defuse_Base**。
2. 使用 ARM Compiler 5；本机验证版本为 **V5.06 update 7 build 960**，Keil 路径 `E:\keil5`。若本机路径不同，在 Keil 中选择已安装的 Compiler 5。
3. Rebuild，确认 0 Error / 0 Warning。下载器应为 **ST-Link Debugger，SWD**。专用 SWDIO/SWCLK 接口照旧连接。
4. 舵机先断电或卸下摇臂。经 ST-Link 下载，复位。OLED 首页应为“拆弹箱基础检查”。串口出现 `DEFUSE BOX BASE V1.0 ZH READY`。如果仍显示迷宫，就不是本版固件。

可直接使用 `release/Defuse_Base.hex`；包内附对应 AXF，Keil 工程通常通过 AXF 下载。工程 XML 保持 UTF-8 无 BOM，避免此前的 Cannot read project file 问题。

## 接线速查

供电沿用用户已确认的接法：ST-Link 3.3V → STM32 3.3V，GND → GND。小模块 VCC 用 3.3V；舵机用已调通的独立 5V，并共地。不要把独立 5V 接到主控 3.3V。

| 模块 | 信号接线 |
|---|---|
| OLED | SCL PB10 / SDA PB11 |
| IMU | SCL PB6 / SDA PB7 / AD0 GND |
| 光敏模块 | AO PA1；DO 不接 |
| 编码器 | A/CLK PA6；B/DT PA7；C/GND 接地；若有 VCC 接3.3V；SW不接 |
| KEY1 / KEY2 / KEY3 / KEY4 | PB12 / PB15 / PB8 / PB9，各按钮另一有效触点接地 |
| 蜂鸣器 MH-FMD | I/O PB14；低电平响；VCC3.3V / GND |
| LED1 / LED2 | PA0 / PB0，各串独立限流电阻后接 LED 阳极，阴极接地 |
| SG90 | 信号 PA8；电源独立5V、共地 |
| USB 转串口 | RXD PA9 / TXD PA10 / GND；3.3V逻辑，VCC不接 |

详细供电、上拉、按钮和卡扣见包内 `design` 图纸。ST-Link 对整套新增负载的供电余量仍需实测。

| 顺序 | 操作 | 应看到什么 | 不符合时先检查 |

图纸中的“KEY1确认、KEY3提示”等是将来游戏的按键定义，本基础版按下述检查规则运行。

## 四个页面的实际操作

- 上电首页：KEY1～KEY3只记录按键；旋钮改变 ENC；KEY4下一页。
- 光敏页：显示 RAW 和 AVG；KEY4下一页。
- IMU页：显示加速度、ID、有效样本数 N 和错误数 E；陀螺仪完整数据用 STATUS 查看；KEY4下一页。
- 舵机页：KEY1开启/关闭，KEY2停止，KEY3蜂鸣器短响，旋钮每格约10µs调整，KEY4返回首页并关闭舵机。若KEY1和KEY2同时触发，停止优先。

舵机始终限制在 **1400～1600µs**，50Hz，开启从1500µs开始。每次有效调整刷新15秒操作计时，超过15秒关闭；其他页面也持续执行计时。当前没有“锁位”和“开位”标定，更没有把某个角度宣称为已适合你的机构。先完成空载测试，后续再扩展机构标定。

## Tera Term 中文版设置与命令

选择 USB 转串口对应 COM 口。串口设置：115200、8位数据、无校验、1停止位、无流控。发送换行可用 CR 或 CR+LF；命令区分单词和空格，不区分英文大小写。可打开本地回显看见输入文字。

```text
HELP
STATUS
PAGE 1
PAGE 2
PAGE 3
PAGE 4
BEEP
LED2 ON
LED2 OFF
ENC ZERO
IMU RETRY
SERVO ON
SERVO US 1450
SERVO US 1500
SERVO US 1550
SERVO OFF
```

- `STATUS`：显示显示屏状态、IMU身份/是否有新数据/样本数/数据年龄/错误数、六轴数据、光敏原始与滤波值、编码器、按键、舵机和脉宽。`TX_DROP`是串口发送队列放不下而丢弃的消息数，正常低频交互应为0。
- `PAGE 1..4`：切页，同时停止舵机。
- `IMU RETRY`：先停舵机，再重新初始化。初始化会有合计约300ms的传感器复位等待，属于开机/手动诊断过程；运行采样不使用这些长延时。本基础版没有姿态零点校准和游戏解除检测。
- `SERVO US`：必须先开启舵机；参数必须是1400～1600之间的四位十进制数字。范围外、字母、额外尾巴都拒绝，不会执行。
- 一行最多63个ASCII字符。收到超长或非法字符会丢弃直到换行，避免把被截断的尾巴当新命令。遇到 `RX OVERFLOW`，先单独按一次回车，再重发短命令。

## 软件结构与验证边界

`User/main.c`负责检查页面、输入解析和任务调度；`Hardware/controls.c`负责20ms按键消抖、TIM3编码器、ADC1、TIM1舵机与提示输出；`imu.c/check_i2c.c`沿用已调通的双身份传感器驱动；`display.c`分块更新OLED；`platform.c`负责毫秒时基和中断串口队列。发送消息不会逐字节阻塞等待串口。

ADC读取和IMU读取约20ms调度一次，屏幕内容约100ms更新一次；主循环持续处理按键、串口和输出计时。I²C故障仍可能占用有超时上限的短等待，实际采样速率要以N增长和串口状态判断。

已完成的软件检查和真实Keil编译结果见 `VALIDATION.md`。`Previews/基础诊断页面.png` 来自实际显示代码与模拟数值，不是实物照片。看到N/E示例99999或加速度极限值只是为了检查显示边界。

本工程未通过你的实体板验收。建议反馈：启动横幅、四个按键回显、一组无遮挡STATUS、一组遮光STATUS、一组改变姿态后的STATUS，以及舵机是否能小幅动作和停止。
