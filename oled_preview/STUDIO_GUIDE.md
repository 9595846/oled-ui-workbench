# 通用 OLED 编辑器

本轮新增 `/studio`，仍使用 128×64 单色屏幕。启动原有 `start_editor.cmd` 后，点击顶部“通用编辑器”。也可在本次服务地址后加 `studio`。旧版基础检查页面和原有草稿继续保留，不自动迁移或覆盖。

## 建议先做一个数值输入弹窗

1. 新建项目，输入项目名称和保存名称（汉字、英文、数字、下划线、短横线，项目名称部分最多 32 字符）。
2. 将初始文字改成 `VALUE {value}`。`value` 是默认变量，初始值为 0。
3. 点“弹窗”，将弹窗类型改成“数值输入”，标题可用 `VALUE`，绑定变量 `value`，设置最小值、最大值、每格步长。
4. 在“当前页面按键动作”中，把 KEY1 设为“打开”这个弹窗。
5. 点击模拟 KEY1，再点右转，然后 KEY1 确认。画面中的变量变化；KEY2 取消则不提交数值。
6. “重置模拟状态”恢复设计初始值。保存只保存设计，不把试玩的变量结果写回初始值。

弹窗具有提示、确认/取消、数值输入三种配置。当前提示与确认弹窗都提供 KEY1 确认、KEY2 取消；区别在用途与配置，尚未实现不同按钮布局。数值弹窗增加临时数值输入，限制上下界。弹窗打开时拦截其他页面按键；确认或取消关闭当前弹窗，再执行配置动作。

## 页面与动作

支持新增、复制、删除页面，每项目最多 32 页，每页最多 32 元素。复制页的跨页跳转保留原目标；请检查是否需要修改。删除页会清除指向该页的动作，并调整其他跳页索引。删除弹窗会清除打开该弹窗的按键动作。上述操作可撤销。

可插入文字、图片、弹窗。文字可以使用 `{变量名}` 显示整数变量。变量名称可用汉字、英文字母或下划线开头，后续可包含数字，最长 24 字符。当前变量编辑入口为 JSON，例如：

```json
{"value": 0, "score": 10}
```

变量最多 32 个，整数范围 -999999～999999。删除仍被动作或弹窗引用的变量会被拒绝。文字缺字、未定义变量和越界会提示；不会自动生成中文字模。

每个页面可给 KEY1～KEY4、LEFT、RIGHT 绑定一项动作：不执行、打开弹窗、关闭弹窗、跳页、设置变量、增加变量。设置或增加变量时输入数值，允许负数。当前一项事件执行一个动作，不支持条件判断、动作脚本、多动作链或真实硬件函数。

选中元素后可拖动画布移动它，或让画布获得焦点后用方向键微调；Shift 每次移动 8 像素。点击画布上的文字、图片或可见弹窗会自动选中，显示绿色范围框，并切换右侧属性；重叠时优先最上层可见元素。范围框不写入导出的 PNG。弹窗从元素列表选中后自动展开设计预览；点击“试开此弹窗”可进入运行模拟。模拟时可选择元素查看属性，拖动请先重置模拟。元素按列表顺序绘制，后插入图片会覆盖前面的文字，弹窗始终位于最上层。

## 图片

选择 PNG、JPEG 或 BMP，文件不超过 1.5 MB。可以设置目标尺寸、完整显示留白或居中裁剪、黑白阈值、反色。先看待插入预览，满意后插入。

- 整屏图片：128×64。
- 小图标：例如 16×16、32×16。
- 透明区域按白色处理；默认深色转换为 OLED 亮像素，可勾选反色。
- 插入后保存的是单色像素，不依赖原图片路径。
- 已插入图片如需换尺寸或重新调整阈值，重新导入后删除旧图。
- 当前不支持抖动算法、动画或拖动裁剪框。

导出 PNG 是当前模拟/编辑画面的原始 128×64 像素。图片上传只到本机服务，不上传外部网站。

## 项目与预设

“保存项目”写入 `drafts/project_名称.json`。更换保存名称可另存；同名文件存在时需要先打开它，不能跳过修订号保护直接覆盖。新建、重新打开会检查未保存修改。

“当前页存为预设”写入 `drafts/preset_名称.json`，带上该页元素、图片、弹窗、按键动作与项目变量。当前预设以整页为单位，不是单元素模板。

插入预设会新增一页，副本独立于原预设。如果项目已有同名变量且初始值不同，会先询问是否使用项目现有值。同名预设不静默覆盖；请换名保存新版。

单页预设只允许跳转本页。含跳往其他页的动作时，会明确拒绝保存；请先将这些动作改为“不执行”，插入新项目后再绑定目标页。这样避免在另一个项目中出现无效或错误引用。

撤销/重做最多 100 步，仅保存在当前网页内存。文件保存采用修订号检查及文件锁；网页和 MCP 对同一草稿更新时仍会检测冲突。模拟过程不保存。

## 字库与工程适配

通用项目不再读取指定 Keil 工程的 `main.c`，渲染使用 `oled_preview/fonts/` 内复制的现有 ASCII 和中文字模。这个字库是已知起点，不表示所有工程都有同样字库。新工程实际显示驱动、字库和按键代码仍需在未来 C 导出/集成阶段核对。

现有 MCP `read_draft`、`update_draft`、`inspect_preview` 可使用 `project_名称` 或 `preset_名称` 操作通用项目。`read_pages` 仍返回旧基础检查四页，不冒充通用项目。更改通用项目时保留 version=2 和完整结构、使用读取到的 revision。

## 中文适配与点击选框更新

新建项目默认使用“中文设计预览”。已有 v2 草稿未设置模式时保持“严格使用现有工程字库”，可手动切换并保存。设计模式在现有字库之外使用本机 Windows 宋体（C:/Windows/Fonts/simsun.ttc）生成 12×12 单色预览字模；不复制或分发系统字体。常用汉字和中文标点可以预览，缺少字体或不支持的字符仍明确报缺字。新字模仅用于电脑设计，不代表实体工程已支持，未自动修改固件字库。

变量可使用中文，例如 `{"温度":25}`，文本填写 `温度：{温度}`。项目和预设保存名称也支持汉字。按键标签已汉化，弹窗显示“1确认 2取消”。老项目中自定义的英文内容不会擅自替换。

点击元素出现绿色范围框，右侧自动切换文字、位置与弹窗功能属性。框表示文字占用范围或图片/弹窗矩形，选中弹窗会自动展示。范围框是编辑辅助，不包含在屏幕 PNG 中。点击空白隐藏选框。

本轮修改：core.py、studio.py、web/studio.html、web/studio.js；新增 chinese_font.py、test_chinese.py。中文模式/严格字库、中文变量与名称、弹窗汉字共 3 项测试通过；原核心 6 项和通用模型 6 项通过。Chrome 实际点击不同文字、重叠弹窗、编辑栏切换、选框和拖动测试通过，截图在 verification/chinese-selection.png。本轮未编译 Keil 或做实物验收。
插入入口已统一为右侧【＋ 插入元素】按钮：展开后选择文字、弹窗或图片。普通单击屏幕元素即可切换属性，无需双击。

## C 文件导出（当前工程适配）

顶部新增“导出 C 文件”。它导出当前设计快照（不含模拟运行结果），在本机 `oled_preview/exports/project_保存名称/` 生成文件，同时显示路径和每个文件的下载按钮。未保存的编辑也包含在这次快照中；导出不等于保存工作台项目。无压缩包，不创建新的 Keil 工程。

- `ui_design.json`：设计源数据。
- `ui_assets.c/.h`：图片、所需中文字模和布局数据，字模会实际嵌入导出代码。
- `ui_pages.c/.h`：使用当前工程 display_pixel/display_clear 的绘图代码。
- `ui_actions.c/.h`：按键、旋钮、弹窗和变量操作；不直接操作硬件。
- `接入说明.md`：工程加入文件、事件接入和旧逻辑冲突说明。
- `manifest.json`：来源指纹、变量编号、资源估算及验收状态。

相同名称再次导出会更新同一目录的生成文件；若发现上一次导出文件被手工修改，拒绝覆盖，需换名导出。当前工程适配指纹来自 export_profile.json；如果指定工程的驱动、主循环或工程配置变化，导出会要求先重新核对适配。

MCP 新增 `export_ui(name, expected_revision)`，只导出已保存的通用草稿。例如读取 `project_我的界面` 后，用返回的 revision 导出。网页与 MCP 使用同一个生成器，均不修改固件、不编译、不烧录。

应用步骤：先审阅设计和接入说明，确认要替换的原页面/按键行为，再将三个 .c 加入当前 Keil 工程并接入接口。现有舵机安全逻辑、后台采样不能被新按键逻辑意外覆盖。不会自动应用本轮导出。

验证：示例生成 C 代码在 GCC 下通过 -Wall -Wextra -Werror；10 个含图片、中文、弹窗确认/取消、翻页的状态与 Python 预览帧缓冲逐像素一致；本机 E:/keil5/ARM/ARMCC/bin/armcc.exe 编译 ui_assets.c、ui_pages.c、ui_actions.c 均返回 0。此结果是模块编译，不是完整 Keil 工程链接，更不是实物测试。每次新导出 manifest 仍标记未单独编译验收，避免把示例结果当成任意项目结果。

网页验收补充：浏览器实际点击导出并下载 ui_assets.c，下载文件与本地生成文件 SHA256 一致；HTTP 与 MCP 导出测试通过。原 firmware 基线 126 个文件哈希全部未变。
